本模块包含两个并列的独立 CMake 项目，均作为 SDK 消费方的冒烟测试：
- `examples/full-stack-host`：构建名为 `authforge-full-stack-smoke` 的可执行文件，通过 `find_package(authforge-drogon)` 引入完整产品栈（含 Drogon、OpenSSL、CURL 等传递依赖），并直接复用 `apps/server/src` 下的 `bootstrap/ControllerRegistration.cc`、`IdentityAssembly.cc`、`OrganizationController.cc` 以及 `apps/server/views` 中的 `.csp` 视图（经 `drogon_create_views` 编译进二进制）。程序启动后在后台线程运行 Drogon 服务器，等待 `registerBeginningAdvice` 回调完成控制器注册与身份服务装配，再通过内嵌 `HttpClient` 对 `http://127.0.0.1:6789` 发起 HTTP 请求，断言 `/health`、`/.well-known/openid-configuration`、`/login`（渲染 login.csp）、`/oauth2/authorize`（未认证重定向）四个验收点。
- `examples/third-party-host`：构建名为 `third-party-host-smoke` 的最小可执行文件，仅链接 `authforge::oauth2`、`authforge::common`、`authforge::common::testing`、`authforge::storage::memory` 四个 SDK 包，不依赖 Drogon/OAuth2Plugin/PostgreSQL；使用 `MemoryClientRepository`、`FakeCryptoProvider` 等内存后端组装 Domain 层的 `AuthorizationService` + `TokenService`，以回调形式调用 `evaluateScopes` → `generateAuthorizationCode` → `exchangeCodeForToken` 完成授权码流程核心步骤。
两个示例均以退出码 0/1 表达通过/失败，并通过顶层 CTest 的 `SdkSmoke.FullStack` 入口由 `ctest --build-and-test` 驱动，模拟外部消费者通过 `find_package` 消费 SDK 的真实路径。
