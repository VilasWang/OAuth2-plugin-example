顶层 CMakeLists.txt 按设计文档的 Domain/Adapter/Drogon 分层顺序依次 add_subdirectory：先 libs/common → oauth2 → identity（Domain 层），再 storage-postgres/memory/redis（Adapter 层），最后 libs/drogon 与 authforge-server；tests 挂载在 server 之后以便复用其目标，examples/third-party-host 通过 find_package 验证 SDK 可独立消费，full-stack-host 通过 ctest --build-and-test 作为外部消费者冒烟用例。
conanfile.py 是跨平台依赖唯一来源，把 with_identity / with_social / with_webauthn 三个特性开关映射为 CMake 缓存变量 WITH_IDENTITY/WITH_SOCIAL/WITH_WEBAUTHN，使 libs 各子模块共享同一份可选编译门控。
manage.sh / manage.ps1 作为统一入口，读取 paths.env（源码/构建/SQL/配置路径的唯一真相源）并委派到 scripts/backend/* 下的具体脚本，同时桥接前端 npm 命令与 Docker Compose 编排。
tools/ 与 scripts/ 共同构成 CI 质量门禁：前者守护 API 表面、Domain 架构规则、SQL 迁移基线与 OpenAPI 签名，后者负责构建、测试、Docker 编排与安全扫描，二者均依赖顶层 CMakePresets.json 与 conan.lock 保证工具链一致。
