模块包含两个完全独立的 Vite + Vue 3 单页应用，分别位于 `frontends/admin` 和 `frontends/user`，通过各自的 `package.json`、`vite.config.ts`、`Dockerfile` 独立构建与部署。

- 应用分层：每个应用遵循 `src/main.ts` → `App.vue` → `router/index.ts` → `pages/*`（页面路由）→ `components/ui` 与 `components/shared`（可复用 UI 组件）→ `stores/auth.ts`（Pinia 状态）→ `services/*`（HTTP 客户端、错误归一化、消息目录）的单向依赖结构。
- 认证流程：admin 采用 JSON 模式直接 POST `/oauth2/login` 获取 code 再换 token，refresh_token 持久化到 `sessionStorage`；user 走标准授权码/设备码回调流程，token 由 `services/http.ts` 管理。两者均在 `axios` 拦截器中自动附加 Bearer Token，并在 401 时触发去重化的 refresh 重试，失败后调用 `redirectToLogin`。
- 错误处理统一：`errorAdapter.ts` 实现 `Frontend_Error_Module`，将 axios 错误按 Error Envelope / RFC 6749 / 未知 / 网络失败四种优先级归一化为 `NormalizedError`，并通过 `messages/zh-CN.ts` 输出本地化文案；admin 中的该文件是 user 端的字节级镜像，由 property test 保证一致性。
- 国际化：各应用通过 `services/messages/index.ts` + `zh-CN.ts` 暴露 `getErrorMessage`，默认语言为 zh-CN。
- 测试：每个应用均使用 Playwright 编写 e2e 用例（`tests/e2e/*.spec.ts`）与 Vitest 单元测试（`tests/unit/smoke.test.ts`），admin 额外使用 fast-check 做属性测试。
- 部署：各自带 `nginx.conf` 与 `Dockerfile`，admin 以 `/admin/` 为 base path 部署，user 以根路径部署，开发期通过 vite proxy 转发到后端 `http://127.0.0.1:5555`。
