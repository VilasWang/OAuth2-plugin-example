- 所有脚本通过 `source env_common.sh`（或 Windows 等价文件）加载共享环境变量，禁止硬编码项目路径，路径变更只需修改 `paths.env`。
- 构建/测试脚本统一通过 `resolve_cmake_preset "$BUILD_TYPE" "$SANITIZER"` 解析 preset 名，再派生 `build/<preset>` 输出目录，保证本地与 CI 行为一致。
- 每个功能脚本同时提供 Linux/macOS (`*.sh`) 与 Windows (`*.bat`/`*.ps1`) 双实现，命名一一对应（如 `build.sh` ↔ `build.bat`、`test-admin-endpoints.sh` ↔ `test-admin-endpoints.bat`）。
- 脚本以 `set -e` 或 `set -euo pipefail` 开启严格错误模式，并使用 ANSI 颜色变量（GREEN/YELLOW/RED/NC）输出结构化日志。
- Docker 相关操作统一通过 `docker-compose -f $COMPOSE_FILE_ABS ...` 调用，Compose 文件路径来自 `paths.env` 的 `COMPOSE_FILE_REL`，避免硬编码相对路径。
- 测试类脚本采用“先构建、再切换至 preset 目录、最后 ctest”的固定三步流程，并在失败时保留构建产物以便调试。
