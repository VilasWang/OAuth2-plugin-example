模块遵循 design.md §4.1 的分层依赖规则，将代码拆分为相互独立的 CMake 子包：
- Domain 层（无 Drogon 依赖）：`libs/common` 提供 Result<T,Error>、值对象（Subject/Scope/ClientId/PkceChallenge/TenantId 等）、端口接口（ISubjectResolver/IRoleProvider/IUserInfoProvider/IClock/ICryptoProvider/IUuidGenerator/IEmailSender/ILogger/IMetrics）及 AuditEvent；`libs/oauth2` 实现纯协议逻辑（PKCE、授权/令牌服务、同意+范围决策引擎），仅依赖 `authforge::common` 且与 `libs/identity` 互不依赖；`libs/identity` 实现身份域（AuthService/MfaService/WebAuthnService/SocialAuthService/SessionManager），依赖 `authforge::common` + OpenSSL。
- Adapter 层（允许 Drogon/OpenSSL/CURL）：`libs/drogon` 是 Drogon 绑定层，持有插件装配器、Controller、Filter、View，并显式链接所有 storage-* 包以组装 OAuth2Plugin；`libs/storage-memory` / `libs/storage-postgres` / `libs/storage-redis` 分别提供内存、PostgreSQL（含 drogon_ctl 生成的 ORM 模型）和 Redis 实现的 oauth2 仓库接口（IClientRepository/IGrantRepository/ITokenRepository/IConsentRepository），并实现 identity 仓库接口。
- 依赖方向严格单向：storage-* → oauth2/identity → common；drogon 聚合所有层；Domain 层禁止包含任何 `<drogon/...>` 头文件。
- 每个子包均为独立可构建的 CMake 目标，通过 `authforge_package()` 导出 `authforge::*` 命名空间别名，并使用统一的 `oauth2_apply_compat/warnings/gcov` 工具链宏。
