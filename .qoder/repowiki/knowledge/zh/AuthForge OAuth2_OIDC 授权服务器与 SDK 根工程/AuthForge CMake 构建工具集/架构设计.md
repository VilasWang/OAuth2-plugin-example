本模块以一组独立的 `.cmake` 脚本构成共享 CMake 工具层，被根 `CMakeLists.txt` 及各 `libs/*` 子项目通过 `include()` 引用，彼此之间无相互依赖，仅由调用方按需组合：
- 版本与路径：`Version.cmake` 集中定义 `OAUTH2_PROJECT_VERSION_*`；`Paths.cmake` 解析仓库根 `paths.env` 的 `KEY=VALUE` 行并暴露 `OAUTH2_PATH_*` 变量，同时通过 `CMAKE_CONFIGURE_DEPENDS` 实现文件变更重配。
- 包导出：`AuthForgePackage.cmake` 暴露 `authforge_package()` 函数，配合模板 `AuthForgePackageConfig.cmake.in` 在 install 树与 build 树（`${CMAKE_BINARY_DIR}/authforge-cmake/<pkg>/`）同时生成 `<pkg>Config.cmake`、`<pkg>Targets.cmake` 与 `ConfigVersion.cmake`，并通过 `find_dependency()` 注入传递依赖闭包，统一导出命名空间 `authforge::`。
- 编译器适配：`Compatibility.cmake` 的 `oauth2_apply_compat(target)` 通过强制包含 `orm_compat.h` 解决 Drogon ORM 生成代码在 C++17/20 下对 `std::codecvt_utf8_utf16` 的缺失；`Warnings.cmake` 的 `oauth2_apply_warnings(target)` 为第一方目标启用 `-Wall -Wextra`/`/W4` 并可选提升为错误（`AUTHFORGE_WERROR`）。
- 质量工具：`Sanitizers.cmake` 提供 `OAUTH2_SANITIZER`（off/thread/address 三态枚举）开关，向目标追加 `-fsanitize=thread|address` 编译与链接选项；`Coverage.cmake` 提供 `OAUTH2_TEST_COVERAGE` 开关，为目标追加 gcov 覆盖标志并显式链接 `gcov`（GCC）。
所有函数均遵循同一边界契约：校验目标存在、按编译器分派、将选项设为 `PRIVATE` 以避免污染导出接口。
